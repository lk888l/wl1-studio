# WL1 参数保存到 Flash

运动工作台的“机身与重心”、姿态环、速度环、差速环、横滚环，以及腿高自适应设置均提供“保存到 Flash”。每个入口执行同一个整组保存操作：**将小车当前 SRAM 中全部可持久化运动参数写入 Flash**，并非只保存按钮所在的一组。

## 使用方式

1. 通过串口或蓝牙直连小车，确认固件兼容，并允许本次连接写入；也可连接 Mock 体验界面。
2. 修改草稿后，使用原有逐项或“下发本组”按钮将需要变更的参数发送给小车。仅编辑输入框不会改变小车。
3. 点击任一“保存到 Flash”。保存不会自动下发草稿，不会自动应用本地档案，也不会覆盖其他组的草稿。
4. 等待当前连接收到 `save: ok` 或 `save: unchanged`。前者表示已保存，后者表示与已保存记录一致、无需重复写 Flash。

“已下发 / 已请求”只表示发送记录，不能证明每个草稿值均被小车接受。保存成功确认的是**设备当时的参数快照**，不是界面草稿与设备逐项回读一致。电脑中的“本地参数档案”仍只保存草稿，独立于小车 Flash。

分组按钮、自适应腿高按钮和诊断终端的 `save` 共用保存事务。保存期间各入口共用等待状态，阻止重复操作。未连接、只读连接或遥控器桥接模式禁用保存；后端继续执行写入权限和命令白名单检查。切换连接、断连或取消等待后，不会将旧结果当作新会话的成功。

## 固件来源与保存范围

本次核验于 **2026-09-25** 读取 [WL1 固件仓库](https://github.com/lk888l/wheeled-legged_Robot-WL1) 的本地工作树。HEAD 为 `428f199d48a4e462334d897019d0ecef7bfb78d1`（2026-09-23，`feat: add UID and persistent auto-leg commands`），且相关源码和文档存在未提交修改；不能只凭此 commit 判断实际烧录镜像。旧 `8f8eb82` 基线的“仅 RAM”说明不适用于此保存实现。

核验依据为固件仓库内：

- `car_firmware/Component/UserApp/Tasks/CommandServiceTask.cpp`：`save` 分发及完整回执。
- `car_firmware/Component/UserApp/MotionParameterCommands.hpp`：只接受无参数、`all` 或 `recycle`。
- `car_firmware/Component/UserApp/MotionPersistence.cpp`：保存时复制当前参数，启动时恢复。
- `car_firmware/Component/UserApp/MotionParameterJournal.hpp`：追加、去重、满日志和回读校验。
- `car_firmware/docs/commands.md`、`car_firmware/docs/runtime-flash-save.md`：协议及普通保存与回收的区别。

| 保存到 Flash | 保持瞬态，不保存 |
|---|---|
| 俯仰重心基准、自适应腿高角度中心（横滚偏置 `roll_bias`） | 速度目标、左右轮速差 / 转向目标 |
| 角度、速度、差速、横滚四组 PID 的 P/I/D | PID 历史、遥控超时计时 |
| 共同腿高、横滚目标 | `control on/off`、安装模式 |
| 角度 Kp 自动 / 固定模式、电机死区、自适应腿高开关 | 诊断 / 遥测开关、硬件 UID |

`R` 的 height / roll 与 `legheight` / `target_roll` 更新相同的持久字段，因此它们会进入保存快照；`R` 的 turn / velocity 及 `VandD` 的目标不保存。该表描述固件的完整范围，不表示上位机已经提供所有字段的编辑入口。UID 是硬件只读标识，无需保存。

启动时恢复最后有效记录；没有有效记录时使用固件默认值。未保存的 SRAM 修改在复位或断电后丢失。后续遥控帧仍可更新腿高和横滚目标，因此保存后继续遥控可能再次产生未保存的变化。

## 自适应腿高角度中心

“机身与重心”组新增角度中心，默认 0°。这是独立的横滚零点偏置，补偿后横滚角 = 原始横滚角 + 偏置。例如车身处于期望中点时原始 Roll 为 +2.5°，将角度中心设为 −2.5°后点击“下发”，发送 `rollbias -2.5`；再点“保存到 Flash”发送 `save`，固件会将 `roll_bias` 与其他运动参数一起保存。

上位机输入范围为 −20° 至 +20°，步长和下发精度为 0.1°，与现有俯仰偏置采用相同的校准范围；这是上位机范围，当前固件只要求完整有限数值，没有该范围硬限制。关闭自适应腿高后此值仍保留并用于姿态门控；`R.roll`、共同腿高和 `autoleg` 开关不会覆盖它。

串口或蓝牙直连时，在诊断终端输入不带参数的 `rollbias` 可只读查询：`rollbias base=-2.5000 raw=2.5000 effective=0.0000`。分别表示当前设置的偏置、最近一次 IMU 原始横滚角及补偿后横滚角。查询不修改本地草稿；也不能独立证明已经保存到 Flash，仍需核对保存回执及断电后结果。遥控器桥接尚不支持本项设置或查询。

## 指令与结果

上位机发送规范命令正文 `save`。串口直连沿用无行结束符的 UART idle 帧，现行 `UartCommandFramer` 仍接受此格式；蓝牙使用 `@save\n`（LF 为 `0x0A`）并按已有传输层分包。固件也接受 `save all`，但普通保存入口仅发送 `save`，不暴露任意保存参数。

接收端先按行重组通知，再识别当前会话的 RX 日志。以下是固件回执前缀及处理方式：

| 回执 | 界面结果 |
|---|---|
| `save: ok (all motion parameters)` | 保存成功 |
| `save: unchanged (no flash write)` | 参数已保存，本次未重复写入 |
| `save: busy; ...` | 固件忙或正在启动；本次未确认保存 |
| `save: full; use save recycle to erase journal and save` | 参数日志已满，提示维护处理 |
| `save: invalid parameters` | 参数无效，保存失败 |
| `save: flash error; RAM settings retained` | Flash 写入失败，SRAM 调参值仍保留 |
| `save: usage: save [all\|recycle]` | 固件拒绝命令格式 |

发出请求后 **10 秒**未收到有效结果，显示“无法确认参数是否已写入 Flash”，不将串口 / BLE 写入完成或无线 ACK 当作保存成功。超时、断连和错误均不会自动重试；超时也不能证明 Flash 没有写入。由于协议没有请求编号，超时或发送结果不确定后需断开并重新连接小车，才能再次保存，避免迟到回执被下一次请求误认；同时核对固件版本。旧固件可能只回显或静默，应用不据此猜测支持。

## 普通保存与维护

正常 `save` 支持平衡运行中追加记录，不要求 `control off`；应用不会附带 `control off/on`，也不会因保存而执行重启。相同参数返回 `unchanged`，减少重复写入。

日志满时，普通保存返回 `full`，不会自动擦除。`save recycle` 是独立维护操作，需要支撑车体、停止控制、未解锁且左右 PWM 为零；擦除窗口掉电可能丢失旧记录。**上位机普通保存按钮和诊断白名单不开放回收命令**，应按对应固件维护流程处理。整片 Flash 擦除也会清除设备参数。

遥控器桥接尚未开放保存命令，也没有小车保存结果回传。需要保存时改用串口或蓝牙直连；无需为了普通保存刷写固件镜像，前提是当前镜像已经实现上述协议。

## Mock 与验证边界

浏览器预览与 Tauri Mock 支持保存回执演示：首次保存返回 `ok`，没有修改设备参数时再次保存返回 `unchanged`；只有下发或实际发送的运动目标会改变模拟设备状态，仅编辑草稿不会改变保存内容。界面标明 Mock 仿真回执；模拟状态不构成真实 Flash 或跨进程持久化。

本次改动未连接实体小车验证保存。自动化及 Mock 不能替代以下台架验收：

- 下发已核对参数，保存后复位 / 断电，再确认 PID、共同腿高和自适应腿高开关恢复。
- 未下发草稿不会因点击保存而写入设备；跨组保存遵循完整快照范围。
- 同值保存返回 `unchanged`；忙、日志满、Flash 错误和超时不会被误报成功或自动回收。
- USB / BLE 分片、断连与重新连接不会让旧回执污染新会话；运行中保存的实际控制时序仍需实测。

执行真实运动和断电测试前，遵循[安全指南](safety.md)。
