# WL1 蓝牙遥控（ZX-D30 单模 BLE）

WL1 桌面工作台通过原生 BLE 连接 ZX-D30 单模 BLE 模块，使用系统蓝牙适配器，无需创建 COM 口。纯浏览器预览仅提供仿真，GameBox / NFC 等其他产品继续使用各自的设备服务。

## 连接与遥控

1. 打开电脑蓝牙和小车电源，断开微信小程序或其他客户端与模块的连接。
2. 进入 WL1，在顶部选择 **蓝牙 BLE → 扫描**，按模块的实际广播名称选择 ZX-D30。扫描不依赖固定名称，连接时会核对透传服务。
3. 默认只读。如需遥控，勾选本次连接的“允许遥控与调参”，然后连接。该许可不写入本地偏好，切换设备或重新连接需要再次选择。
4. 蓝牙连接后进入 **实时遥控**。明确选择本次腿高（44.5–78.5 mm），点击“启用实时控制”，按住 W/A/S/D、方向键或屏幕按钮移动。可同时按前进和转向。
5. 松手发送速度、转向、横滚归零帧，保留腿高。空格 / Esc / “立即停止”停用控制；窗口失焦、隐藏、离开页面或连接故障也停止。返回窗口或重新连接后不会自动恢复运动。

前进对应固件负速度，与参考小程序一致；右转对应正转向。默认幅度 18，可在 0.5–100 范围调整。横滚范围 ±18°。设置腿高与滑块本身不会自动启动运动；设备不回报实际腿高，界面展示的是选定或请求发送的目标。

软件停止依赖通信，不能替代物理断电。初次联调请保持车轮架空、人员远离机构。BLE 连接与 GATT 写入成功不代表固件已执行，更不代表车辆处于平衡状态。

## 协议与固件要求

当前使用单模 BLE 模块。本次参考用户提供的 ZX-D30 V1.4 手册中的 BLE 接口、[微信小程序](https://github.com/lk888l/cf-studio_wechat-app)（参考提交 `8c396240756b4f39c2e7f7ead6b92fb6fe538036`）以及 `car_firmware/docs/zx-d30.md` 和当前命令 / 控制任务源码。

| 项目 | 实现 |
| --- | --- |
| BLE 服务 | `0000FFE0-0000-1000-8000-00805F9B34FB` |
| 写入 | 优先 FFE2，缺少时回退可写 FFE1；优先 write with response |
| 接收 | 订阅 FFE1 notify / indicate，保留通知分片并复用逐行解析器 |
| FFE3 | 不作为 UART 使用，避免向模块 IO 控制通道写入 |
| BLE 帧 | `@<ASCII 命令>\n`；正文不超过 32 字节 |
| BLE 分包 | 每片最多 20 字节，片间留 25 ms，整条命令串行发送 |
| 帧截止时间 | 自入队起 200 ms；超时关闭连接，不重试或补发尾片 |
| 遥控周期 | BLE 为 100 ms（10 Hz）；只保留最新待发目标 |
| 模块 ↔ MCU UART | 配套 ZX-D30 固件为 9600、8N1、无流控；BLE 本身没有串口波特率设置 |

蓝牙入口要求支持显式分帧的 **WL1 SoftEngine 固件**。所提供源码允许 300 ms 内完成分帧，并在连续 500 ms 无有效运动命令时将生效速度、转向和横滚归零，保持共同腿高和正常平衡控制。应用不会自动探测或保证其他已烧录镜像具有同样保护。

USB 串口入口仍保留旧固件 idle 帧兼容；可选择 9600 / 115200。遥控器 NRF 桥接仍固定 115200，并保留实体摇杆控制运动的边界。应用不自动发送模块 AT 命令，不改变模块名称、UUID、UART 波特率或配对配置。

## 遥测与带宽

真实连接默认关闭连续遥测。当前固件的全速 IMU + RPM 输出会超出 9600 baud 的可用吞吐，蓝牙遥控时建议保持关闭；需要连续曲线时应在模块和 MCU 两侧同步提升 UART 速率并单独验证，或使用合适的有线链路。上位机不会自动配置模块内部 UART。

收到的 FFE1 文本会进入现有遥测 / 诊断通道。已开启遥测时，现有数据新鲜度保护继续有效。接收队列溢出、通知流关闭、设备断连、超长行或写入失败都会锁定并清理会话，旧会话请求不能进入新连接；不自动重连或恢复写入。

## 平台与排障

- **Windows**：BLE 需要支持低功耗蓝牙的适配器并打开系统蓝牙。
- **Linux**：使用 BlueZ 和 D-Bus；构建需要 `libdbus-1-dev`，运行需要 `bluez`。`scripts/bootstrap-ubuntu.sh` 已包含这些依赖。无需以 root 运行应用。
- **macOS**：使用系统 CoreBluetooth；包内提供蓝牙用途说明，首次使用需系统蓝牙授权。本次未在 macOS 实机验证。
- 扫不到设备时检查模块电源、系统蓝牙开关、无线距离，以及是否仍被手机占用；扫描可能包含系统缓存设备，连接超时后请重新扫描。
- 服务不匹配时确认模块 FFE0 / FFE1 / FFE2 配置。任意改写 UUID 的模块不在本版自动匹配范围。
- 连接成功但车不响应时，核对 SoftEngine 固件、模块与 MCU UART 速率和 TX/RX 交叉接线；确认本次写入许可、腿高选择和本地控制已开启。不要绕过固件 IMU 门控。

## 验证

`npm run check` 执行前后端回归。蓝牙专项覆盖 UUID 通道选择、帧边界、20 字节分片、超时不补尾片、通知重组、断连后的读写拒绝、前进符号、10 Hz 发送、最新目标合并、松手归零、只读保护及会话隔离。

可选的本机发现测试只扫描，不连接或发送数据：

```sh
cargo test --manifest-path src-tauri/Cargo.toml bluetooth_scan_smoke -- --ignored --nocapture
```

自动测试不驱动车轮或舵机。真实 BLE 收发、断电 / 断连后的物理停止和带负载运动仍须在目标平台与台架验证；固件仓库已有联调记录不能替代本上位机的实机验收。
