# WL1 固件与 Flash（STM32F411CEU / ST-Link SWD）

在产品首页进入 **WL1 → 固件与 Flash**。probe-rs 0.32.0、芯片定义和 Flash 算法直接编入桌面程序；运行时不启动或下载 probe-rs CLI、OpenOCD 或 STM32CubeProgrammer。源码首次构建仍需正常下载 Cargo/npm 依赖。

烧录引擎与 USB 设置材料均内置，安装版和源码编译运行使用相同流程。驱动/权限只在用户手动确认并通过系统授权后设置；应用启动、构建和安装包都不会自动执行设置。不要以 root/管理员身份启动整个应用。

## 首次 USB 设置（无需另行下载）

1. 在“烧录器与目标”中展开“USB 驱动与权限设置”，阅读设置说明和第三方驱动许可。
2. 已能识别且访问 ST-Link 时可直接操作；否则点击“设置 USB 支持（系统授权）”。
3. 在应用确认弹窗中点“继续设置”，随后由操作系统请求管理员授权。取消授权会返回明确错误，不会伪报成功。
4. 完成后重新插拔 ST-Link 并刷新列表；Windows 如提示重启，请保存工作后手动重启。

Windows 10/11 **x64**：程序内嵌未修改的 STSW-LINK009 ZIP（调试驱动 2.02），原始文件、SHA-256、来源和 SLA0048 许可见 [`resources/stlink`](../src-tauri/resources/stlink/NOTICE.txt)。固定 PowerShell 脚本通过 UAC 请求授权，把 ZIP 复制到管理员专用临时目录，重新核对哈希及原版签名，使用系统 PnPUtil 安装唯一的 `stlink_dbg_winusb.inf`。不执行随包旧版安装器，不安装 VCP/bridge INF，不强制替换更高优先级驱动，不自动重启。正常结束会清理临时文件。Windows ARM64 不提供此离线驱动安装入口；企业策略拒绝安装/脚本执行或签名信任异常时需管理员处理，不绕过策略。

Linux 桌面：使用系统已有的 `/usr/bin/pkexec` 和 polkit 授权代理，仅写入 `/etc/udev/rules.d/70-wl1-stlink.rules` 并重载规则。规则匹配 ST VID `0483` 和已知 ST-Link PID，使用 `TAG+="uaccess"` 授权活动本地桌面用户，不使用全局 `0666`，不改动串口组。已有完全相同的规则可重复设置；同名规则内容不同或是符号链接时拒绝覆盖。无 polkit/udev 的精简系统、SSH/无本地桌面会话环境或受管机器需管理员预配置 USB 权限；应用不会下载/安装系统软件。

macOS 通常不需要 ST-Link USB 驱动，本项目尚未进行 macOS 构建与硬件验证。

USB 设置本身不会连接/写入芯片，且与烧录、读取、擦除及串口会话互斥。其后正常硬件操作不需要应用以管理员权限运行。卸载应用不自动移除共享 Windows 驱动或 Linux 规则；若不再需要，管理员可审查后通过系统驱动管理或删除上述唯一规则并重载 udev 撤销授权。

## 接线与目标

操作前断开电机电源，保持主控供电，与 ST-Link 共地，连接 SWDIO、SWCLK 和目标参考电压。按板卡要求使用 3.3 V 电平，不要把参考电压输入误认为供电输出。首次验证应在架空、可物理断电的台架进行。

先断开上位机中的串口或 Mock 会话。ST-Link 使用 USB/SWD，不通过 WL1 串口，不需要固件侧 bootloader 或升级协议。

轮腿产品固定使用 **STM32F411CEU / 512 KiB**，页面只读展示型号，不再提供其他芯片或容量选项。主 Flash 地址为 `0x08000000`–`0x0807FFFF`（包含末尾），probe-rs 使用内置 `STM32F411CEUx` 目标。

后端读取 `DBGMCU_IDCODE` 校验器件系列 ID `0x431`，读取 `0x1FFF7A22` 的实际容量并核对固定的 512 KiB。系列或容量不符时拒绝操作；成功结果包含 UID 和实际 SWD 频率。探针按 VID/PID/序列号重新定位，重复序列号会被拒绝，需要只连接一个匹配探针。游戏机使用独立的固定 F103C8T6 配置，见 [GameBox 接入指南](gamebox-integration.md)。

默认 SWD 为 1000 kHz。连接不稳定可降到 400/100 kHz。设备固件关闭调试引脚或普通连接失败时，可接上 NRST 再选择“复位下连接”。过旧的探针固件仍需通过 ST 官方工具维护，应用不更新探针自身固件。

完整读取、擦除后的空白检查及独立文件校验按 16 KiB 更新进度，通过 probe-rs 的批量读取接口使用 32 位访问；驱动按探针上限拆包，避免 ST-Link V2 的 8 位读取每次只能传输 64 字节。烧录时，在扇区擦除成功后跳过内容全部为空白值的原始页，减少工厂固件空洞及空白保留区的无效写入；这些页仍参加完整回读校验。未覆盖数据中的非空白内容照常恢复，禁用擦除或使用编码算法时不跳页。默认频率保持 1000 kHz。

F411 / 512 KiB 使用两个 16 KiB RAM 编程缓冲区，减少原先每 1 KiB 就配置核心寄存器并启动算法的往返。原始 `stm32f4xx_1024` 的 `ProgramPage` 按传入长度循环写 32 位字；16 KiB 对齐所有擦除扇区，双缓冲、算法和栈均在 F411CE 的 128 KiB RAM 内。逐页超时按缓冲容量同比例增加。优化只对已核对指令 SHA-256 的内置算法生效，其他算法、OTP、物理扇区、Flash 容量和芯片识别规则保持原配置；升级算法后哈希不符时回退原始缓冲设置。

## 三个独立操作

### 烧录 / 更新

1. 选择已下载的 `.bin`、Intel `.hex`、32 位 ARM 小端 `.elf` 或 `.axf`。
2. BIN 默认起始地址 `0x08000000`；有 bootloader 时须按固件发布说明设置应用地址。HEX/ELF 使用文件内的绝对加载地址；ELF 的 RAM 初始化内容按 Flash 加载地址处理。
3. 核对 SHA-256、写入字节数和地址段，在确认弹窗中检查目标与文件。
4. 等待未覆盖字节保存、扇区擦除、写入、回读校验完成；随后自动复位启动。

无需先点独立擦除。烧录会自动擦除涉及的扇区，并恢复这些扇区中不属于固件文件的字节；不涉及的扇区保持原样。新固件比旧固件小时，旧尾部仍会保留，需要彻底清空时先手动擦除。

文件必须非空且不超过 16 MiB，装载数据必须全部在产品主 Flash 范围内。检查拒绝损坏的 HEX 校验和、缺少结束记录、重叠数据、错误 ELF 架构和越界加载地址。烧录前后端重新解析并核对已确认的哈希。

SHA-256 与格式检查不是发布方签名认证，也不能证明固件适用于这块电路板。

### 擦除

输入 `ERASE` 确认后，清空全部主 Flash，包括 bootloader、应用和其中的参数。随后读取完整范围，确认每个字节为 `FF`。

使用明确的地址范围擦除，不使用会遍历其他非易失区域的 `erase_all`。不会修改 OTP、选项字节或读保护。擦除不可撤销，需要备份时先读取并导出；擦除后必须重新烧录才能使用。

### 读取

从 `0x08000000` 读取全部 512 KiB 主 Flash，包括尾部空白区，结果包含 SHA-256。读取临时暂停核心，退出调试后设备可能继续运行。

视图每页 256 字节，每行 16 字节，显示地址、十六进制及 ASCII；支持输入地址跳转及原始 BIN 导出。备份标明芯片 UID 与读取时间；后续写入/擦除后旧快照标为过期，仍可导出。切换工作台内页面不会丢失快照；返回产品首页或关闭应用前请导出需要保留的数据。

完整读取指主 Flash，不包含系统引导 ROM、OTP、选项字节和 RAM。读保护导致失败时不会返回不完整的“成功备份”，也不会自动解除保护。

## 生命周期与失败处理

操作在 Rust 后台线程执行。进度来自 probe-rs 事件或实际读取字节；独立擦除的时间不确定阶段显示不定进度，每个阶段的百分比独立计算。

全局固件任务锁与产品会话锁阻止并发硬件操作和串口重连，成功/失败均释放。操作期间阻止正常窗口关闭与退出；强杀进程、拔线或断电仍可能留下不完整固件。擦除/烧录不提供立即取消按钮。

烧录或校验失败后保持电机断电，修复供电/接线/占用问题再重试。提示“校验通过，但复位失败”时可手动重新上电确认运行。权限、接线和保护错误保留底层原因；禁止自动解锁时的破坏性擦除。

浏览器预览的硬件操作被禁用，不产生虚构成功结果。

## 验证边界

自动化覆盖格式、容量/地址边界、ELF 物理地址、HEX 校验和/EOF、芯片身份、任务互斥、内置目标与算法、完整 512 KiB 数据最后一页和浏览器禁用路径。USB 测试覆盖确认门禁、内置驱动哈希与许可、PowerShell 路径转义/编码、取消与需要重启的结果；Windows CI 额外解析设置脚本并验证原版驱动签名。普通测试不会请求管理员权限、安装驱动、写入系统规则或连接硬件。

### 2026-11-13 Windows 实机性能验证

设备为 ST-Link V2-1（V2J48M35）与 STM32F411CEU / 512 KiB。优化前后均使用 1000 kHz 设置，探针实际为 950 kHz；使用同一 Rust test 构建配置及桌面命令共用的 `execute_job` 后端。固件为用户提供的 `WL1_F411CEU6_factory.bin`，393,300 字节，SHA-256 为 `c426d116e28c7b222e71080e75d1ddae313e21ebf9c8cdca31d09835ddfdd876`。

| 操作 | 优化前 | 优化后首轮 | 变化 |
| --- | ---: | ---: | --- |
| 完整读取 512 KiB（含连接、恢复状态和计算哈希） | 130.598 s | 8.430 s | 约 15.5 倍速度 |
| 独立逐字节校验完整 512 KiB 备份 | 130.970 s | 8.423 s | 约 15.5 倍速度 |
| 工厂固件烧录（含保留、擦除、写入、校验、复位） | 41.568 s | 24.409 s | 耗时降低约 41% |
| 其中实际编程阶段（按状态变化计时） | 22.625 s | 5.425 s | 耗时降低约 76% |

最终方案第二轮在发布构建并行时同样通过，完整读取 8.498 s、完整校验 8.499 s、烧录 28.250 s；结果见 `optimized-bulk-repeat/`。两轮均执行下面的完整回读、局部写入与错误检测。最终再由 OpenOCD 独立读取全部 512 KiB（`final-openocd.bin`）核对后复位运行。

烧录未启用“内容相同就跳过擦写”，每轮实际执行涉及扇区的擦除。写后比较整个 512 KiB：文件范围与固件相符，其余字节与写前备份相符。另从同一固件抽取跨 `0x08004000` 边界的 9 字节做局部烧录，确认两个受影响扇区的其余非空白程序及其他全部 Flash 字节保持一致。未对齐首尾、跨读取块及 Flash 最后 5 字节校验通过；故意将 `0x0807FFFF` 的期望字节改错后，后端报告该地址不一致并释放任务锁。

初始独立备份由 OpenOCD 读取，完整 Flash SHA-256 为 `137af7fb8e30c37dacd152294337c95f28b2541994d7ed472b7e0e87e825fd71`。本地备份和逐阶段计时保存在被 Git 忽略的 `captures/wl1-stlink-20261113/` 中，原版为 `baseline/`，最终方案首轮为 `optimized-bulk-1000/`。

排查中曾出现两次烧后回读校验不一致，均按失败停止；独立复核时未发现持续的 Flash 内容差异，其中一次独立首次回读也有单字节差异、再次读取则恢复一致。没有通过忽略校验、自动重烧或屏蔽通信错误来处理。ST-Link 同时报告约 0.58 V，按该探针已知的电压误报情况继续实测；这些结果不代表已定位瞬时读回差异的硬件原因。

复测入口如下。`WL1_STLINK_BASELINE` 必须是当前目标的独立完整 512 KiB 备份；默认只读取与校验，仅在显式设置 `WL1_STLINK_FLASH=1` 并指定固件后才会烧录和测试局部保留。

```powershell
$env:WL1_STLINK_PROBE = '0483:374b:01290141524300143638414B'
$env:WL1_STLINK_BASELINE = 'D:\path\current-full-flash.bin'
$env:WL1_STLINK_OUTPUT = 'D:\path\new-validation-directory'
$env:WL1_STLINK_SPEED = '1000'
# 执行实际烧录时额外设置：
$env:WL1_STLINK_FIRMWARE = 'D:\path\WL1_F411CEU6_factory.bin'
$env:WL1_STLINK_FLASH = '1'
cargo test --manifest-path src-tauri/Cargo.toml --lib --locked wl1_stlink_performance_and_preservation -- --ignored --nocapture --test-threads=1
```

上述实测仅覆盖当前 Windows、ST-Link V2-1、F411CEU 和 BIN。ST-Link V3、其他实物目标、HEX/ELF 实机烧录、独立整片擦除后全 FF 校验、读保护拒绝、拔线报错、复位下连接及空白 Windows/Linux 的 USB 支持仍需单独验证。
