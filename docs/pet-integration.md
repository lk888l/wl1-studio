# ESP32-C3 桌宠接入与创作

产品库中的 **ESP32-C3 像素桌宠** 使用独立的 **Pet Studio** 工作台。
对应固件工程是 `espc3-integrated`，OLED 分辨率为 **128 × 64**。
桌宠模式占用整个屏幕，USB 断开后仍继续运行。

## 从样式到屏幕

1. 在产品库点击 **进入桌宠工作台**。
2. 通过 USB 连接 ESP32-C3，在 **USB 设备** 中选择对应串口，例如 `/dev/ttyACM0`，点击 **连接设备**。
3. 左侧选择 **灵动双眼 / Orbit**、**团子猫 / Mochi**、**长耳兔 / Bunbun** 或 **布丁史莱姆 / Pudding**。
4. 点击 **在设备显示这个样式**，直接切换到设备内置宠物。
5. 右侧 **陪它玩一会儿** 提供八个动作按钮，可同步触发设备表情。

连接时会查询 `pet status` 确认兼容固件。浏览器中可以完整编辑、预览与导入导出工程，真实 USB 连接需要运行 Tauri 桌面应用。
工作台切换与应用退出会释放持有的串口，其他产品的命令不会进入桌宠连接。

## 自定义像素和动画

点击 **自己画一个** 创建空白宠物，也可以修改任意预设作为起点。
画布为 **64 × 32** 单色像素，固件以整数 **2 倍**缩放铺满 OLED。
画笔、橡皮支持拖动连续绘制，也可用方向键移动像素光标、空格绘制。
支持当前帧撤销、清空和反相。

动作按固定顺序为：

| 动作 | 标识 | 设计用途 |
| --- | --- | --- |
| 待机 | `idle` | 自然陪伴与张望 |
| 眨眼 | `blink` | 短暂闭眼后睁开 |
| 开心 | `happy` | 月牙眼、蹦跳和小星星 |
| 吃东西 | `eat` | 张嘴、咀嚼或靠近食物 |
| 睡觉 | `sleep` | 闭眼休息，显示 Z |
| 惊讶 | `surprised` | 睁大眼睛和圆嘴 |
| 委屈 | `sad` | 下垂眉眼和委屈嘴形 |
| 跳舞 | `dance` | 上下摆动、切换装饰 |

每个动作最多 **4 帧**，全部动作最多 **24 帧**；待机至少 **1 帧**。
其他动作可留空，固件使用待机画面。
通过 **新帧 / 复制 / 删除** 调整动画，点击缩略图选择帧；帧间隔为 **80–1000 ms**。
右侧播放按钮仅控制本地动画预览。
四套预设工程均包含八动作、每动作两帧，可继续编辑。

在 **从图片开始创作** 中导入 PNG、JPEG、WebP 等图片，图片等比缩放并居中到当前帧。
亮色转为 OLED 发光像素，透明部分按黑色处理；黑白阈值和反转明暗可即时调整。
图片大小上限为 10 MB，动画图片只导入一张静态画面。

宠物名称为 **1–16 个可打印 ASCII 字符**，例如 `Mochi`、`MyPet-01`。
名称不符合要求时显示提示并保留此前有效草稿，不覆盖本地存储。

点击 **上传并在设备显示** 后，工作台生成 PET1 像素包，逐块上传、校验并保存到设备。
上传成功后自动进入自定义宠物模式。当前设备保存 **1 个自定义宠物槽**；下一次成功上传会替换这个槽。
可导出多个 JSON 工程作为本机宠物收藏，再按需要导入和上传。

## 保存与分享

- 当前有效草稿自动保存在浏览器或桌面应用本地的 `studio.esp-c3.pet.v1` 中。
- **导出 JSON** 保存完整 `wl1-pet-v1` 工程，包含名称、八动作、时序与像素帧。
- **导入工程** 校验画布尺寸、名称、帧内容、帧数和间隔，拒绝损坏或超出设备容量的数据。
- **下载 PET1 像素包** 导出与设备上传一致的 `.pet` 二进制包；上位机编辑入口使用 JSON 工程。
- 本地草稿与设备自定义槽独立：修改草稿后需要上传，设备才会使用新像素。

## 设备按键

| 操作 | 设备动作 |
| --- | --- |
| 上 / 下键 | 切换前 / 后一个宠物，包含已下载的自定义宠物 |
| 确认键单击 | 开心 |
| 确认键双击 | 吃东西 |
| 确认键长按 | 睡觉 |
| 同时按上、下键 | 返回主页 |
| 左 / 右扩展键 | 调整视线 |
| Jump 扩展键 | 跳舞 |
| Function 扩展键 | 惊讶 |

设备待机时自动呼吸、张望和眨眼，闲置 **60 秒**后入睡。
睡眠中按任意按键会先唤醒，此次按键不执行原动作。
左右、Jump、Function 为可选扩展键，默认硬件不一定连接。
上位机八个动作按钮始终可用于对应 USB 控制。
点击 **退出设备桌宠模式** 返回设备主页；点击 **断开** 只释放 USB，宠物继续运行。

## USB 协议

独立串口为 **115200 baud / 8N1 / 无流控**，命令为 ASCII 单行，以 LF 结束。
后端只接受完整独立的 `pet_ok ...` 或 `pet_error ...` 回执行，跳过 ESP-IDF 日志、命令回显与提示符。

```text
pet status
pet open 0
pet action happy
pet close
pet begin SIZE CRC32
pet chunk OFFSET HEX
pet commit
pet abort
```

样式编号：`0` 双眼、`1` 猫、`2` 兔、`3` 史莱姆、`4` 自定义。
`CRC32` 是 IEEE CRC-32 的八位十六进制文本，`OFFSET` 是十进制字节偏移，`HEX` 每块最多 64 字节。

上传每步严格等待 ACK。`begin` 校验 `bytes`，每块校验 `next=OFFSET+长度`，`commit` 校验 `bytes` 与 `crc`。
上传进度根据已确认字节推进，设备完整校验并提交后才显示保存成功。
取消或提交前失败会尽力发送 `pet abort`，不把半包作为新宠物。
超时或 IO 错误会使 USB 会话失效，不自动重发修改命令；设备拒绝命令则保留仍可用的会话。

Tauri API 为 `pet_connect({ portName })`、`pet_disconnect({ expectedSessionId })`、`pet_snapshot()`、`pet_command({ expectedSessionId, command })`。
前端与 Rust 均维护会话编号，排队动作在断开后取消，旧会话不会写入新连接。

## PET1 格式

| 偏移 | 字节数 | 内容 |
| --- | --- | --- |
| 0 | 4 | ASCII `PET1` |
| 4 | 4 | `64, 32, 8, 0` |
| 8 | 16 | ASCII 名称，不足补零，最多 16 字节 |
| 24 | 8 | 八动作各自帧数，范围 0–4，`idle >= 1`，总和不超过 24 |
| 32 | 16 | 八动作帧间隔，uint16 小端，80–1000 ms |
| 48 | 16 | 保留为零 |
| 64 | N × 256 | 按动作顺序紧密排列的帧 |

每帧 64 × 32 像素、256 字节，按行存储，每字节最高位对应最左像素。
这与 OLED 驱动的页缓冲布局不同，设备负责转换和缩放。
最小包 **320 字节**，最大包 **6208 字节**。

## 验证

前端测试覆盖四套八动作模板、行优先 MSB 像素、PET1 头和动作顺序、标准 CRC-32 向量、最大容量、非法 JSON 与名称、保存失败、离线创作、会话隔离、上传 ACK、失败与取消后的 abort。
本次实现通过 `npm run typecheck`、`npm run lint`、`npm test` 和 `npm run build`。
固件的构建、烧录与实机验证记录见配套 `espc3-integrated` 工程中的桌宠文档。
