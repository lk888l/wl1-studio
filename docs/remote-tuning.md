# 通过遥控器无线调参

连接路径：电脑 → USB 转串口 → WL1 遥控器 USART1 → NRF24L01 → 小车。

## 固件前提

原版 `tele_firmware` 的 USART1 只输出调试日志，没有启动 RX 或串口转发。仅更新上位机不能让原版遥控器收到参数；必须先刷入配套 **WL1 串口桥接 v1** 固件。配套源码为 [WL1 固件 9cc2f95](https://github.com/lk888l/wheeled-legged_Robot-WL1/tree/9cc2f953b472331a41afc5c495d42867fd80a54c/tele_firmware)，构建和协议见其中的 `docs/serial-bridge.md`。

串口使用 **115200 baud、8N1、无流控**。按该仓库 `Core/Src/usart.c` 的引脚配置，USB 转串口 TX 接遥控器 RX（PA10），RX 接遥控器 TX（PA15），并连接 GND；使用 3.3 V 逻辑电平。遥控器与小车需要使用匹配的 NRF 地址、信道和速率。串口能打开只说明电脑连接到串口设备，不能证明遥控器固件正确、小车在线或无线链路可用。

## 使用步骤

1. 更新遥控器桥接固件，给遥控器和小车上电，架空小车并准备物理断电。
2. 进入 WL1 工作台，点击连接，选择 **USB 串口 → 通过遥控器**，刷新并选择遥控器对应串口。
3. 确认桥接固件和现场条件后连接。不勾选确认项时，仅查看遥控器日志，不能发送参数。
4. 连接后进入参数调校，逐项下发或按组发送 PID。Angle Kp / 姿态偏置仍需逐项请求，自动计算语义取决于小车固件版本。
5. 诊断页查看 TX 和遥控器的转发结果。无线失败时可点同一参数的“重发请求”；不会自动重试。参数仅写入小车 RAM，断电或重启会丢失。

## 功能范围

| 功能 | 直连小车 | 通过遥控器 |
|---|---|---|
| 四组 PID、anglebias | 支持 | 支持下行转发 |
| anglepid auto / anglebias auto | 依赖小车固件版本 | 依赖小车固件版本 |
| 参数草稿、档案、运动学实验室 | 支持 | 支持 |
| 腿高、电脑实时 R 控制 | 支持 | 使用实体遥控器摇杆 |
| IMU / RPM、采样标定 | 支持 | 当前桥接无回传 |
| 参数读回、执行 ACK、Flash 保存 | 不支持 | 不支持 |

遥控器每 50 ms 持续发送摇杆 `R` 目标。电脑不发送 `R` 或 `legheight`，避免争夺运动控制权或让腿高立刻被周期帧覆盖。断开电脑连接只关闭串口，不会停止遥控器的摇杆控制。

## 协议边界

- 配置字段 `connectionTarget` 为 `robot`（默认）或 `remote`；`mode` 仍表示 `serial` / `mock`。旧配置缺少目标时按直连处理，Mock 始终模拟小车。
- 直连保持原有 idle 分帧：不追加换行，正文最多 32 ASCII 字节。
- 遥控器桥接使用 LF 行分帧：正文最多 **31 ASCII 字节**，由 Rust 自动追加 LF。固件将正文补零为 32 字节 NRF 载荷。诊断输入不需手动追加换行。
- Rust 串口写入后至少等待 **120 ms**，覆盖单项、诊断和批量入口；批量操作还保留前端间隔，并在页面/会话变化时取消待发任务。
- TypeScript、Rust 和桥接固件分别校验命令。只开放 PID / anglebias，拒绝 `R`、`legheight`、`showimu`、`showrpm` 及未知命令。
- 遥控器日志保留在终端，不作为小车姿态、轮速、链路质量或电压解析；没有遥测也不会触发原有小车遥测超时。
- TX 仅说明串口写入完成。NRF 投递结果只反映无线模块发送结果，不是小车参数执行 ACK。无线失败不会自动重发参数；检查连接后再明确重试。

## 验证与台架检查

本次自动化检查覆盖目标默认值、前后端能力限制、31/32 字节边界、LF 分帧、旧会话取消、遥控器日志隔离和退出时不发送小车关闭命令；固件另有解析器测试与交叉编译。

未连接实体遥控器和小车执行调参测试。首次台架联调应检查：原版固件不会被误认为可调参；桥接收到单条和连续命令；无线模块投递日志随小车断电正确变化；参数在小车侧生效；调参过程中摇杆发送持续；拔出串口后实体遥控器仍正常。参数效果必须由实机观察或小车直连读取确认。
