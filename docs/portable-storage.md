# 便携式配置与关闭设置

在产品库打开 **个性设置 → 关闭窗口时**，可选择：

- **最小化到托盘**（默认）：释放工作台界面及其他产品连接，保留电脑监控的 Wi-Fi 采集与发送；从系统托盘重新打开控制中心。
- **全部退出**：结束界面、托盘和后台任务。下次启动是否恢复传输仍由原来的启动设置决定。

选择立即生效，保存成功后重启继续保持。显式“轻量后台运行”按钮始终进入后台，托盘“退出”始终完整退出。系统托盘不可用时关闭窗口会完整退出。固件忙时仍然阻止正常关闭。

## 保存在哪里

| 运行方式 | 用户配置目录 |
| --- | --- |
| `npm run tauri dev`，含开发模式 release 构建 | 工程根目录的 `.local` |
| Windows / 普通 Linux 发布程序 | 可执行文件旁的 `.local` |
| Linux AppImage | 外部 `.AppImage` 文件旁的 `.local`，不是内部挂载目录 |

目录在主进程启动时确定，不依赖命令行当前目录；发布程序不使用开发者工程路径。实际位置显示在个性设置页。

目录内的两个文件均为 JSON：

- `background-v1.json`：关闭行为、启动偏好、监控配置和传输恢复状态。
- `user-config-v1.json`：个性设置、参数档案、WL1 连接偏好、监控表单、校准记录、桌宠像素工程、电子琴工程、StickS3 串口和网络地址。

复制程序或备份项目时，同时复制 `.local` 即可带走全部已保存内容。项目已忽略 `.local`，个人数据不会随 Git 提交。先退出程序再手工修改或复制配置文件。

这些文件包含用户创作的工程和档案，应作为用户数据备份，不应当作可随意删除的缓存。手工导出的 NFC、固件、桌宠等备份继续保存在用户原先指定的位置；WebView 引擎缓存、驱动安装临时文件和实时采样内存不纳入迁移。纯浏览器预览继续使用浏览器存储。

## 旧数据与异常处理

首次启用时自动复制旧系统目录的后台配置，并在首次打开界面时迁移原 WebView 内的九类已保存数据。新目录已有内容优先，只补缺项；完成迁移后不再反复导入。旧文件和旧浏览器数据保留作为备份。把已初始化的 `.local` 带到另一台机器后，不会混入目标机器的旧设置。

配置损坏时保留文件并显示恢复界面，不用默认值覆盖。可修复后重试，或选择备份损坏配置并重置。损坏后台配置不会自动恢复发送。

如果程序目录不可写，设置仍可在本次会话中使用，界面显示失败原因和实际目录，不自动改存 AppData。请将程序移到可写目录；Linux 系统安装目录和只读介质也可能遇到这一情况。

保存成功提示只在原生写入确认后显示。关闭窗口、轻量后台和托盘退出前，会等待自动保存队列，并提交桌宠编辑器尚在防抖等待中的修改。电子琴、校准等需要手动保存的编辑仍需点击保存。保存失败时保留窗口，可重试、继续编辑，或明确放弃未保存内容后继续关闭。

配置接口仅允许固定的九类键。配置消息上限为 16 MiB，超限时拒绝写入并保留原数据；普通监控和控制消息仍限制为 16 KiB。

## 手工验收

1. 分别选择两种关闭行为，保存后立即关闭并重启，确认选择保持；全部退出后检查托盘和后台进程均结束。
2. 运行监控后进入托盘，确认设备会话与序号连续；恢复窗口后配置仍完整。
3. 编辑桌宠后立即关闭、点击轻量后台或从托盘退出，确认最后一次已自动保存的编辑可恢复。
4. 在程序退出后复制程序及 `.local` 到另一可写目录，从不同工作目录启动，确认设置与工程完整恢复。
5. 用隔离配置目录验证首次迁移、重复启动不覆盖、损坏文件恢复和不可写目录提示；不要用唯一一份工程数据做破坏性验证。
6. 在 Linux 分别验证有托盘、无托盘和 AppImage 外部目录，确认不会写入只读挂载目录。
