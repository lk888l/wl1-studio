# 安全指南

WL1 是能够快速改变姿态和驱动轮运动的机电系统。上位机中的一次参数写入或 `R` 目标发送可能立即改变控制行为；操作系统完成串口写入也不代表设备确认，更不代表机械系统处于安全状态。

> [!DANGER]
> 首次联调、未知固件、PID/腿高修改、`R` 组合运动目标以及通信异常测试必须在安全台架上进行：机器人可靠架空或机械固定，驱动轮和腿部无法接触人员或环境，物理急停触手可及，并由能立即断电的人员监护。

## 安全边界

WL1 Studio 负责输入校验、能力检查、状态提示和通信错误处理，但它不是安全控制器。以下保护不能依赖桌面应用实现：

- 物理急停与主电源切断；
- 驱动器电流、速度、位置和温度限制；
- 机械限位和防碰撞结构；
- MCU 通信看门狗和失联安全状态；
- 上电默认禁止输出、使能顺序和故障锁存；
- 电池、充电、保险和接地保护。

桌面进程、操作系统、USB、WebView 或串口任务都可能暂停、崩溃或延迟。任何要求持续收到上位机消息才能保持安全的设计都必须由固件看门狗兜底；Linux 上也不得通过 root 运行来绕过串口权限。

## 操作前检查

每次连接真实设备前确认：

- [ ] 机器人身份、硬件版本和固件 commit/版本已记录；
- [ ] 机器人可靠架空或机械固定，轮和腿的完整运动范围无人员与障碍物；
- [ ] 物理急停已测试且无需依赖上位机；
- [ ] 主电源可立即切断，监护人员知道断电位置；
- [ ] 电池电压、线束、USB 隔离/接地和驱动器状态正常；
- [ ] 当前串口及其 USB VID/PID 确实属于目标设备，而不是同机其他控制器；
- [ ] 选择了正确的协议配置，未知固件保持只读；
- [ ] PID 安全范围、`legheight` 当前值，以及 `R` 的 turn/velocity/roll/height 目标已逐项核对；
- [ ] 串口记录已开启且不会写满系统盘；
- [ ] 没有启用未经验证的自动重连或自动套用参数。

任一项不满足时，停止实机写入，回到 Mock 模式或只读诊断。

常驻连接区的真实设备写锁默认关闭。“允许本次连接遥控与调参”要求操作者确认固件兼容、车轮架空、人员远离机构且可立即断电；写入许可不保存到偏好，切换设备或结束连接后清除。USB Legacy 与蓝牙 SoftEngine 使用不同帧格式，连接成功不替代固件确认；缺少许可时只允许只读连接。蓝牙配置和验证边界见[蓝牙遥控指南](bluetooth-control.md)。

## 操作风险分级

| 等级 | 示例 | 最低要求 |
|---|---|---|
| 只读 | 端口枚举、设备信息、静态状态 | 身份明确，不自动发送未知探测命令 |
| 遥测 | `showimu -y/-n`、`showrpm -y/-n` | 限制开启时长，观察带宽和实时性影响 |
| 高风险控制 | PID、`legheight`、`R` 组合目标 | 安全台架、急停、二次确认、明确字段与范围 |
| 禁止/未实现 | 固件刷写、任意命令、绕过限幅 | 完成独立设计审查和硬件验证前不开放 |

遥测命令也可能切换持续输出并占用 115200 baud 链路，不能因为“不改变参数”就视为零风险。

## 参数修改要求

### PID

错误的增益可能导致高频振荡、冲击、过流、过热或机械失稳。写入前必须确认：

- 控制通道与 P/I/D 参数顺序；
- 参数单位、离散控制周期和固件内部缩放；
- 驱动器限流、速度限制和姿态保护有效；
- 初始值由操作者依据同一台实机的已验证记录确认；应用内置默认值不构成安全基线；
- 每次只做可解释的小幅变化，并观察温度、电流和振荡；
- 发生异常时用物理急停/断电，不等待 GUI 响应。

### `R` 组合运动目标

蓝牙 BLE 入口对应用户提供的 2026-09 SoftEngine 固件：显式 `@...\n` 分帧、300 ms 拼帧期限、500 ms 运动目标超时。蓝牙按 10 Hz 更新，W / 前进采用负速度；窗口失焦或发送失败会停用控制且不自动恢复。下段的 250 ms / 无超时描述保留为旧有线基线记录，不能用于判断实际烧录镜像。

`R` 不是轮径，而是严格按 `R <turn> <velocity> <roll> <height>` 一次更新左右轮目标 RPM 差、平均目标 RPM、横滚角（度）和腿高（毫米）。字段错位或速度符号错误会直接形成非预期运动。当前本地工作树有 250 ms `R` 超时归零，HEAD 基线没有；在缺少版本握手时必须按保护未知处理。发送前从静止/中性目标开始验证，并保证松开控制、通信丢失和窗口失焦时不再持续发送。

### `legheight` 与动态管理参数

`legheight` 的舵机任务限幅是 44.5..78.5 mm，上位机也必须在发送前执行该限制。HEAD 基线会由 MotionControl 每 10 ms 按腿高重算 Angle Kp 与 `anglebias`，因此一次数值发送可能很快被覆盖；当前本地工作树提供手动覆盖并可用 `anglepid auto` / `anglebias auto` 恢复自动计算。缺少版本握手时，界面只能显示“请求已发送”，不能宣称稳定生效。

`R` 的 height 是强制字段。新会话不得擅自假定 44.5 mm 或沿用上次连接的值；操作员必须明确选择本会话腿高，或先成功请求 `legheight`，实时控制才允许解锁。参数页、标定页、受限诊断入口和实时控制共享同一会话目标，但它仍不是设备读回值。

普通批量下发只包含直接支持的 PID 项；会驱动机构的 `legheight`，以及版本相关的 Angle Kp / `anglebias`，必须逐项明确请求。

打开连接弹窗或执行参数发送时必须立即撤销实时控制武装并发送中立目标；离开参数页会取消尚未发送的批量项，不能让 PID 队列与 20 Hz `R` 控制流交错。

不要把界面滑块的视觉范围当作固件安全范围；Rust 侧应使用由具体固件/硬件配置确认的限制，未知时禁止写入。

## SRAM 与 Flash 参数的边界

下发参数先修改 SRAM；支持 `save` 的现行固件可通过“保存到 Flash”显式保存车上全部运动参数：

- 未保存的修改在重启后丢失，固件会恢复最后有效 Flash 记录或默认值，不能把“重启会恢复默认值”当作急停或恢复手段；
- MCU 在复位前仍可能使用危险参数；
- 看门狗复位或棕断可能使界面与设备值不一致；
- 上位机保存的方案只存在电脑中，不能显示为“设备已永久保存”；
- 重连后所有设备参数都应标记为未知，经过回读或人工确认后才能恢复“已确认”状态；
- 默认禁止连接后自动套用上次参数。

各组保存按钮都保存整组设备快照，包括共同腿高、横滚目标、自适应腿高开关和其他已下发参数；它们不自动下发当前输入草稿。只读连接和遥控器桥接禁止保存。只有固件 `save: ok` 或 `save: unchanged` 才按成功显示，超时、断连和失败不自动重试，也不据此判断设备仍为旧值。

普通 `save` 可在控制运行时追加记录，无需关闭平衡；应用不自动发送 `control off/on`。日志满只提示维护，不自动执行 `save recycle`：回收须支撑车体、停止控制，并确保未解锁、左右 PWM 为零；擦除窗口掉电可能丢失已保存记录。实际掉电恢复和运行中保存仍需按[参数保存指南](parameter-flash-save.md)完成实机验证。

## 通信异常

出现以下情况时立即停止新的写入并转入未知/故障状态：

- 串口被拔出或系统报告读写错误；
- 固件在命令执行期间重启；
- 应答超时或无法和请求关联；
- 连续出现乱码、超长行或解析错误；
- 遥测时间戳停滞或队列持续溢出；
- 设备身份、协议主版本或能力集合发生变化。

通信恢复后必须重新识别，不能自动补发超时命令。迟到应答也不能当作新会话的成功结果。WebView 刷新不等于 Rust 后端退出；界面启动时必须先强制关闭可能遗留的设备会话，实时控制在新 `sessionId` 下重新选择腿高并重新武装。清理失败时必须保持连接功能锁定，并持续显示“不能把离线视为已经停止”的故障横幅，而不是继续运行。

本版在已请求开启 IMU + RPM 遥测时采用明确窗口：任一通道 600 ms 未更新，前端就撤销武装并请求中立；任一通道 2 s 未更新、连续 64 行解析失败，或 4096 字节仍无换行，Rust 会锁定会话并触发断开。未开启遥测时不以静默为故障。Rust 读/写故障会先把会话标成不可写，在同一个 writer 临界区中阻止旧的排队命令越过安全帧，随后直接尽力发送 `showimu -n` / `showrpm -n`；若曾实际进入 `R` 或 `legheight` 写入临界区，还会按该次已校验的**尝试腿高**发送三轴归零的 `R`。独立的、核对 `sessionId` 的后端清理线程负责关闭会话，不依赖 WebView 事件回调。写入和 flush 的边界仍可能导致结果未知，所以这些关闭命令均只能视为 best-effort，不能取代固件看门狗或物理断电。

如果固件没有失联看门狗，上位机掉线可能使机器人维持最后目标。完成实机运动前，必须先在固件中验证安全的超时行为。

## 上位机必须提供的安全交互

- 默认进入只读或 Mock 模式；
- 明确显示“模拟设备”和“真实设备”，两者视觉上不可混淆；
- 写操作旁显示目标设备、参数单位、允许范围和 RAM 标识；
- 高风险写入要求用户核对旧值与新值，并执行明确确认；
- 未获得能力、范围或设备身份时禁用写操作并解释原因；
- 发送后区分“已发送”“设备确认”“回读一致”三个结果；
- 连接丢失时立即移除已连接/已应用的视觉暗示；
- 内置诊断终端只允许参数白名单中的单条命令，禁止发送 `R`、未知命令或绕过长度、范围、会话令牌与写入安全锁；
- 停止按钮不能伪装成物理急停，必须明确其依赖软件与通信链路。

## 开发与测试安全

- 单元测试和普通 CI 只能使用 Mock/Replay，不自动枚举或打开串口；
- 实机集成测试需要显式开关、明确端口和人工监护；
- 不在测试代码中硬编码真实端口或自动下发运动命令；
- Fuzz/异常帧测试先在解析器和 Mock 上运行，不能直接轰击未知固件；
- 对 32 字节边界测试应验证“拒绝不发送”，禁止静默截断；
- 所有数值边界包含 `NaN`、无穷大、极大指数、负零和单位错配；
- 自动重连、批量参数方案和未来 CAN/UDP 写入都需要单独安全评审；
- 日志记录应脱敏，并设置大小/时间上限，避免磁盘耗尽影响系统。

## 异常处置

当机器人出现非预期运动、振荡、异响、过热或失控迹象：

1. 使用物理急停或切断主电源；不要等待软件停止命令；
2. 保持人员远离，等待机械部件完全停止和储能释放；
3. 不立即重复连接或重发命令；
4. 保存上位机日志、固件 commit、参数方案和操作时间线；
5. 检查固件复位原因、驱动器故障、电源和机械结构；
6. 在 Mock/回放中复现软件路径；
7. 完成原因分析和保护措施后，才在更低风险的台架条件下重试。

## 当前明确限制

- 现有 feature/framework 固件缺少稳定的版本和能力协商；
- `showimu -y/-n` 的 100 Hz CSV（HEAD 三字段、工作树追加 `a/ok`）和 `showrpm -y/-n` 的 20 Hz A/B 输出会占用串口与控制环时间，只适合短时诊断；
- PID 命令语法已经确认，但固件没有给出全部实机安全上下限；`rollpid` 没有 D，Angle Kp 与 `anglebias` 在 HEAD 被周期覆写、在当前工作树可进入手动覆盖；
- `R` 是四字段组合运动目标，不是配置参数；速度符号和安全范围必须在具体硬件台架上验证；
- 命令正文最多 32 字节；源码未正确 trim LF/CRLF，首版上位机以无结束符的 receive-to-idle 帧发送。该 framing 必须台架验证，固件后续应正式实现分帧与 trim；
- 未执行 `save` 的调参仅在 SRAM 生效；现行固件支持显式整组 Flash 保存与结果回执，旧固件不一定支持，超时不能判定成功；
- CAN 与 UDP 只是架构预留，尚未定义安全的发现、身份和写入协议；
- 上位机不能保证实时性，也不能替代固件侧停止、限幅和看门狗。

任何界面功能若与这些限制冲突，应以更安全的行为为准：隐藏、禁用、只读或要求进一步验证，而不是自动猜测。
